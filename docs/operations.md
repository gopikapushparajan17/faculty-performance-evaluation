# Operations, behavior notes, and known issues

## Local vs S3 uploads

Uploads are handled by `POST /api/upload`.

### Local upload mode (default)

- files are stored under `backend/uploads/`
- backend serves them at `/uploads/*` when the `uploads/` directory exists
- API returns URLs like `/uploads/proofs/<uuid>.png`

### S3 upload mode (optional)

If `S3_BUCKET` is set, the backend uploads to S3 and returns an S3 URL.

Related env vars are documented in `backend/app/config.py` and `docs/backend.md`.

## Upload constraints

Enforced server-side:

- **max size**: 10MB
- **allowed types**: PDF, DOCX, JPG, JPEG, PNG
- **blur detection** (images only): rejects low-quality images using an edge-variance heuristic

## PDF generation

PDFs are generated by `GET /api/pdf/{eid}` in `backend/app/routes/pdf.py` using `fpdf2`.

Current implementation:

- builds a styled header/footer
- prints faculty info (from `Evaluation.faculty` when available)
- prints a points summary table (currently a subset of modules)
- prints total points

## Approval preconditions (important)

Backend approval logic in `POST /api/evaluations/{eid}/approve` requires:

- correct current `Evaluation.status` for the caller role
- for HOD/principal: `signature_image` is required
- **PDF viewed requirement**:
  - backend checks `Evaluation.pdf_viewed_by[role]` exists before allowing approvals

### Current behavior in this codebase

- frontend tracks PDF viewing in `localStorage` via `downloadPdf()` (`frontend/src/lib/api.ts`)
- frontend uses that local tracking to enable/disable the Approve buttons
- **backend does not currently update `pdf_viewed_by` anywhere**, so a “PDF must be viewed” backend check can block approvals unless `pdf_viewed_by` is manually set in stored evaluation data.
